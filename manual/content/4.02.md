We'll present an instruction set and design ready to implement, but once you understand this it'll be much easier to implement your own.

In this design, an instruction is 16 bits and we'll support two instruction *layouts*. Those two formats are differentiated by the 15th (most significant) bit of the instruction.

## instruction[15] = 0

```bits
!Layout of an A-instruction
0 : op
vvvvvvvvvvvvvvv : value
```

When that most significant bit is 0, then we simply write the 15 remaining bits to register `A` (zero-extended to 16 bits), and nothing else.

> Since we're left with 15 bits, `A` can therefore contain values between `0` and `32767`.

## instruction[15] = 1

```bits
!Layout of a C-instruction
1 : op
11 : unused
a : a
cccccc : control
ddd : destination
jjj : jump
```

When that most significant bit is 1, our instruction will (1) **compute** something with the `ALU`, (2) **load** the result into registers, and lastly, (3) optionally **jump** the program counter register `PC` to some address. Here's the format of the instruction:

* **Unused bits**. These bits have no use in the format, and could be put to 0 or 1.
* **Address.** We said earlier that the `A` register could contain an address (pointing to data in the `RAM`) *or* plain data. This bit is set to 1 when the value of `A` is an address, and set to 0 when the value of `A` is plain data.
* **Control.** These are the 6 control bits the `ALU` uses and they define the computation performed. In order: `zx`, `nx`, `zy`, `ny`, `f`, `no`. The computation is performed on the following inputs: the `ALU`'s `x` input is always the content of register `D`; the `ALU`'s `y` input is either the content  of register `A` when `a=0` or the content of the `RAM` data *pointed by* `A` when `a=1`.
* **Destination.** These are 3 independent bits each telling whether to write the `ALU`'s output to `A`, `D`, and/or the `RAM`'s register pointed by `A` (only when `A` is an address, i.e. `a=1`).
* **Jump.** Lastly, these are 3 bits each telling whether to load the address in `A` into the program counter register `PC` (only when `A` is an address, i.e. `a=1`). Remember that the `ALU` outputs a number but also `zr` (output is zero) and `ng` (output is negative). If instruction bit 2 is set, then we should load `PC` if `ng` is set. If instruction bit 1 is set, then we should load `PC` if `zr` is set. Finally, if instruction bit 0 is set, then we should load `PC` if neither `zr` nor `ng` are set.


## All possible computations

The eighteen settings worth naming, in both `a` versions:

```truth
.a = 0 | .a = 1 | .a = 0 | .a = 1
`0`    | `0`    | `D+1`  | `D+1`
`1`    | `1`    | `A+1`  | `M+1`
`-1`   | `-1`   | `D-1`  | `D-1`
`D`    | `D`    | `A-1`  | `M-1`
`A`    | `M`    | `D+A`  | `D+M`
`!D`   | `!D`   | `D-A`  | `D-M`
`!A`   | `!M`   | `A-D`  | `M-D`
`-D`   | `-D`   | `D&A`  | `D&M`
`-A`   | `-M`   | `D\|A` | `D\|M`
```

## One instruction, decoded

`M=D+1` is `1110011111001000`:

```truth
.bits | .field | .meaning
`1` | op | C-instruction
`11` | unused | no effect
`0` | `a` | ALU `y` is `A`, unused here
`011111` | comp | `D+1`
`001` | dest | store into `M`
`000` | jump | never
```

## A program

Add 2 and 3, store the result at address 0:

```
@2        0000000000000010
D=A       1110110000010000
@3        0000000000000011
D=D+A     1110000010010000
@0        0000000000000000
M=D       1110001100001000
```
