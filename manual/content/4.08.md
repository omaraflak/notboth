Three chips.

```truth
.chip | .address from | .data in | .data out
`ROM` | `pc` | — | `instruction`
`CPU` | — | `instruction`, `inM` | `outM`, `writeM`, `addressM`, `pc`
`RAM` | `addressM` | `outM` when `writeM` | `inM`
```

Use the built-in `ROM` and `RAM` primitives rather than the RAM8 from 3.07.
3.07 exists to show what is inside a memory. A 65,536-word memory built from
Registers would be around twenty million gates — a Register is roughly 300 —
and every test vector would have to settle all of them.

Set both address widths to 16, matching the buses. Unused capacity costs
nothing: a memory here is an array the simulator indexes, not a netlist it
settles, so compile and settle times are the same for 65,536 words as for 256.
The contents editor holds only the words you actually write.

## Two memories, not one

Instructions and data live in separate memories, which is the Harvard
arrangement. The CPU presents `pc` to one and `addressM` to the other in the
same tick, and neither waits for the other. A single memory would have to
serve both, which means either two ports or an extra tick per instruction, and
the second option means every chip in this Part needs a notion of which phase
of an instruction it is in.

The cost is that a program cannot write to its own instruction memory. There
is no wire from `outM` to the ROM.

## reset

`reset` reaches the counter through the CPU and forces `pc` to 0. Without it,
the counter starts at whatever its flip-flops settle to at power-on, and the
first instruction fetched is at an arbitrary address. The symptom is a program
that produces partial results, because it began in the middle.
