You'll notice a built-in Screen chip. This is optional, but you can wire it to your computer.

The screen chip is like a RAM but where each address's value is interpreted as a 15bit RGB color:

```bits
!Layout of an RGB screen pixel
0 : unused
rrrrr: red
ggggg: green
bbbbb : blue
```

The addresses are flattened in 1d; therefore, for a screen of size 200x100 pixels, `(x=0,y=0)` has address `0`, and `(x=0,y=1)` has address `200`.

One way to wire this screen to your computer is to make it so addresses above a certain threshold asked to be written by the CPU actually go to the screen instead of the RAM.

Once you put the screen chip in your circuit, you can decide of a resolution. Given that you have 15-bit addresses, you want to save some space for your program's memory, therefore I would advise a size of 100x100 pixels. This leaves `2^15-100x100=22768` free addresses in your RAM for your program's memory. This also means that the screen address starts at `22768`:

- `22768` -> pixel `0`
- `22769` -> pixel `1`
- ...
- `32767` -> pixel `9999`

However, this is not yet set up. So you'd have to Mux/DMux the address coming out of the CPU and route it to either the RAM if it's below `22768` or to the screen otherwise. One such signature could be `ScreenRouter(load, address[16]) -> screen[16], ram[16], loadScreen, loadRam`.
