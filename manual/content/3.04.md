---
num: 3.04
title: Flip-flop
sig: DFF(d, clk) → q
needs: 3.03, the clock
---

A flip-flop samples its input at one *instant* using a ***clock*** and outputs it for the rest of the clock cycle.

We're using the notion of a *clock* here for the first time. This will be just a normal input (not the actual clock chip given to you in the interface), but you should expect the *signal* itself to be passed down from an *actual* clock chip higher up in the chain. So the `clk` input is a signal that goes *up* then *down* periodically.

- `d` — data signal to be held on to. Read it only at the *rising* edge of the clock. What it does *during* the cycle should be ignored.
- `clk` — the clock signal. When the clock goes from low to high (i.e. *rising* edge) is when you sample the `d` value and write it to `q`.
- `q` — whatever `d` was at the last edge.

```wave
!Timing diagram for the flip-flop
clk      1100110011001100
d        1001110001110100
>q       0000111100001111
@4 read
@8 read
@12 read
```

Read the picture at the dashed lines: `d` moves seven times, `q` moves three, always at a *rising* edge of `clk` and always to whatever `d` was at that instant.

::: watch
Give the clock a period comfortably longer than the deepest path of gates it
drives, so the logic has time to settle before the next edge.
:::
