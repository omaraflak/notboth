---
num: 4.07
title: Memory-mapped input and output
sig: no new chip — a consequence of 4.03
needs: 4.03, 4.06
short: Memory-mapped I/O
---

The screen and keyboard regions of 4.03 require nothing from the CPU. A
program draws a pixel by storing a number at an address in `16384 – 24575`;
the CPU executes that as it executes any store, presenting an address, a value
and `writeM`. Whatever is attached to those addresses reads them and displays
them.

The alternative is to encode input and output in the instruction set: a device
number, a `read` instruction and a `write` instruction. Each of those is a
third instruction layout for 4.04 to recognise, a path through the datapath in
4.06 that exists only for I/O, and a set of states the CPU can be in that
ordinary instructions cannot reach. Memory mapping replaces all of it with the
decision already made in 4.03.

This editor has nothing attached to those addresses, so there is no device to
wire. What is testable is the mechanism: store a value at 16384 and inspect
the RAM's contents. A display would have shown it, and the CPU would be
executing the same instruction either way.
