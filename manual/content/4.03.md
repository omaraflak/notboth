`A` is 16 bits and the RAM's address input is 16 bits, so the address space is
65,536 words. Only the lower half of it is reachable by `@`, which carries 15
bits; the upper half can be reached only by computing into `A`.

Which words mean what is a decision made here, not in hardware. The CPU
presents an address and a value and asserts a load line. It has no way to tell
what is on the other side.

```truth
.addresses | .words | .contents
`0 – 16383` | 16384 | working memory
`16384 – 24575` | 8192 | screen
`24576` | 1 | keyboard
`24577 – 65535` | 40959 | unassigned
```

The screen region is 8192 words of 16 bits, which is 131,072 bits, which is a
512 × 256 grid of one bit per pixel. Word *n* holds the 16 pixels starting at
row `n / 32`, column `(n % 32) * 16`.

The keyboard word holds the code of the key currently down, or 0 when none is.
It is written by whatever is watching the keyboard, and read by programs like
any other address.

Nothing in the CPU implements either of these. 4.07 covers what that buys.

::: watch
Build the RAM with an address width of 16, matching the bus, even though early
programs touch only the first few words. A RAM narrower than the address it is
given ignores the high bits, so address 16384 into a 14-bit RAM silently
becomes address 0. The program does not fault; it corrupts working memory.
:::
