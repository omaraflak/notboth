title: Data latch
sig: DLatch(d, enable) → q
needs: 1.00, 1.01, 3.02
---

DLatch takes a single `data` input instead of two (`set`/`reset` in the `SRLatch`), plus an `enable` bit:

- **d** — the value to store.
- **enable** — while it is high the output `q` follows `d`; when it drops, `q` holds on whatever value it had.
- **q** — the stored bit.

The first flaw of the previous model automatically disappears since we can't have contradictory inputs, i.e. asking for a 0 and 1 at the same time.

```wave
!Timing diagram for the gated latch
d        0011011001110011
enable   0011110000011000
>q       0011011111110000
~2-5 transparent — q copies d
~6-10 holds
~11-12 transparent
~13-15 holds
```

However, one problem remains: while `enable` is high the chip is *transparent* (it let's the `d` signal pass through). If you chain multiple DLatches and open the gates (`enable` set to 1), a value can race down the whole chain in one go instead of moving step-by-step — which is undesirable because the machine relies on a value crossing exactly one storage element per tick (whereas here, how far a value travels depends only on gate delays).
